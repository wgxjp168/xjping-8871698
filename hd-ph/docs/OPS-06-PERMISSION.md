# 06 · 权限运营体系

## 6.1 权限模型设计

```
用户(SysUser)
    ↓ 多对多
角色(SysRole)
    ↓ 多对多
权限码(SysPermission.permCode)
    ↓ 注入
JWT Token.permissions = "BIOCHEM,BLOOD,DR_VIEW,..."
    ↓ 解析
Gateway X-Permissions 请求头
    ↓ 下游服务判断
业务操作是否允许
```

## 6.5 账号开通流程

### 标准开通流程

```
申请 → 审批 → 创建 → 通知 → 首次登录修改密码
（约1个工作日）

1. 【申请】
   填写《系统账号申请单》（纸质或系统内申请）
   内容:
   - 申请人姓名、工号
   - 所属机构
   - 申请角色（具体业务需求）
   - 直属领导签字

2. 【审批】
   - 机构管理员审批（本机构普通账号）
   - 县级管理员审批（跨机构/高权限账号）
   - 超级管理员审批（管理员账号）
   审批标准: 最小权限原则，按岗位需求分配

3. 【创建】
   系统管理 → 用户管理 → 新增用户
   □ 用户名: [机构编码]_[姓名拼音首字母]（如 mzsy_zs）
   □ 初始密码: hd2024（用户首次登录强制修改）
   □ 所属机构: 选择正确机构
   □ 分配角色: 按审批结果选择

4. 【通知】
   以纸质形式告知用户:
   - 系统访问地址
   - 初始账号/密码
   - 首次登录操作指引

5. 【首次登录】
   用户登录后系统提示修改密码
   新密码: ≥8位，含大小写字母+数字
```

## 6.6 权限变更流程

### 角色调整

```
触发场景:
  - 人员岗位调整（如护士升为医生）
  - 临时授权（如会诊借用权限）
  - 权限缩减（如操作失误后限制）

流程:
  1. 填写《权限变更申请》（注明原因）
  2. 直属领导确认
  3. 机构管理员/超管在系统执行:
     用户管理 → 选中用户 → 编辑 → 修改角色分配
  4. 变更即时生效（下次登录后token携带新权限）
  5. 记录变更日志（系统自动记录）
```

### 特殊情况处理

```
【人员离职】
  当天: 立即禁用账号（用户管理→禁用，不要删除）
  保留: 操作历史记录（审计需要保留≥3年）
  交接: 工作数据归属本机构，不随账号删除

【账号异常（怀疑被盗用）】
  1. 立即禁用账号
  2. 查询操作日志（系统管理→操作日志→按用户名筛选）
  3. 评估异常操作影响
  4. 修改密码后重新启用（确认安全后）
  5. 填写安全事件报告

【临时权限（≤7天）】
  1. 在备注栏注明临时授权截止日期
  2. 到期后人工检查并收回权限
  3. 建议: 二期开发临时权限自动到期功能
```

## 6.7 数据权限（数据隔离）

```
【当前版本数据隔离规则】

角色                  可见数据范围
─────────────────────────────────
超级管理员            全县所有数据
县级管理员            全县所有数据（统计视图）
机构管理员            本机构（deptId匹配）
普通医生/护士         本机构 + 本人操作的记录
DR技师               本机构DR申请单（checkDeptId匹配）

实现方式:
  - 前端: 菜单/按钮按权限码显示/隐藏
  - 后端: Service层查询时注入当前用户的deptId过滤条件
  - Gateway: 请求头注入 X-User-Id, X-Permissions 供下游使用

【二期规划: 细粒度数据权限】
  - 行级数据权限（只看自己负责的居民）
  - 字段级权限（隐藏敏感字段如完整身份证）
```

## 6.8 权限审计与合规

```
【操作日志记录规范】
每次敏感操作自动记录:
  - 操作时间
  - 操作人（userId + username）
  - 操作IP
  - 操作内容（增/删/改 + 对象ID）
  - 操作结果（成功/失败）

【日志查看】
系统管理 → 操作日志
  筛选条件: 操作人/时间范围/操作类型/模块

【定期审计（每季度）】
  □ 超级管理员账号使用记录检查
  □ 批量数据导出记录审查
  □ 跨机构访问记录检查
  □ 深夜（22:00-7:00）操作记录审查
  □ 账号共享使用排查（同一账号多地同时登录）

【合规要求】
  - 日志保存期: ≥3年（卫生信息安全等级保护要求）
  - 账号实名制: 每个账号对应唯一自然人
  - 密码策略: 90天强制修改，不可使用最近3次密码
  - 敏感操作（删除/导出）需二次确认
```
