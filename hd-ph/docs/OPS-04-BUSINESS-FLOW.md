## 4.2 流程一：下乡体检前期准备

### 参与角色
- **县公卫科**: 制定本年度体检计划，系统录入计划任务
- **乡镇卫生院公卫专干**: 通知辖区居民，准备物资
- **系统管理员**: 确保设备在线，账号正常

### 操作步骤

```
【县公卫科 — 系统操作】
1. 登录系统 → 居民管理 → 搜索目标村/社区
2. 批量筛选本年度未体检居民（filter: checkYear != currentYear）
3. 导出名单 → 下发各卫生院

【乡镇卫生院公卫专干 — 系统操作】
1. 确认辖区居民档案完整性
2. 对新迁入/新增居民提前建档:
   - 居民管理 → 新增 → 填写姓名/身份证/性别/出生日期/住址
3. 打印本次下乡体检花名册

【设备检查】
每天出发前执行:
□ hd-device 服务状态: docker ps | grep hd-device → Up
□ TCP:7100 端口: nc -zv 127.0.0.1 7100 → 连通
□ 目标设备IP能ping通 192.168.20.x
□ 设备日志无连接错误
```

## 4.3 流程二：标本采集与转运

### 村卫生室/下乡现场

```
【现场操作流程】
1. 居民签到
   - 扫描居民身份证 → 系统自动查找档案（或手工搜索）
   - 点击"建体检单" → 选择体检类型（老年人/高血压/糖尿病）
   - 系统自动生成体检单号（如 CK20260325001）

2. 标本采集
   - 采血管贴标签: 打印体检单号条码（与系统体检单对应）
   - 现场录入生命体征（手持采集设备或纸质回填）:
     身高、体重、血压（上下两次）、脉搏、腹围

3. 标本登记
   - 核查标本管编号与体检单号对应关系
   - 填写《转运交接单》（纸质+拍照存档）
   - 标本低温保存（4℃冷藏箱）
```

### 标本转运

```
【转运规范】
- 冷链转运: 2~8℃冷藏箱，不超过4小时
- 运输人员: 双人签字交接
- 到达检验科: 扫描转运单条码 → 系统标记"已到达"

【系统记录】
体检单状态: 0(待体检) → 1(体检中)  [转运到达时操作]
```

## 4.4 流程三：院内检验（设备自动采集）

### 检验科操作

```
【标本接收】
1. 核对标本数量与转运单
2. 检验系统（LIS）录入/扫码接单

【设备上机】
1. 将标本上机前，确认设备与系统的IP配置匹配:
   设备管理 → 查看设备列表 → 确认IP与实际设备IP一致

2. 设备检测完成后自动推送结果:
   设备 → TCP连接 → 192.168.10.30:7100 → ASTM报文

3. 系统自动处理流程:
   device_raw_data(待处理)
     → ASTM解析器解析R记录
     → check_result表（BIOCHEM/BLOOD/URINE/HBA1C分类）
     → 体检单状态自动关联

【结果核查】
医生登录 → 体检单管理 → 点击体检单详情
→ 切换"生化/血常规/尿常规/糖化Hb"标签查看各项结果
→ 异常值系统自动标红（偏高/偏低标记）
→ 医生确认审核 → 状态更新"已完成"
```

### ASTM数据流追踪

```
时间线示例（一次生化检验）:

09:15:32 设备TCP连接  → hd-device [INFO] Device connected from 192.168.20.11:54321
09:15:32 ENQ握手      → hd-device [DEBUG] Received ENQ, sent ACK
09:15:33 数据帧传输   → hd-device [DEBUG] 接收5帧，各ACK确认
09:15:34 EOT结束      → hd-device [INFO] Received EOT, processing message
09:15:34 解析完成     → hd-device [INFO] Parsed ASTM, sampleId=CK20260325001, results=28
09:15:34 入库完成     → device_raw_data id=1234, processStatus=0
09:15:35 定时任务     → 检测到待处理数据 → 写入check_result × 28条
09:15:35 体检单更新   → check_order id=100, 状态 1→2（已完成）

医生端:
09:16:00 刷新体检详情 → 生化标签显示28项结果，3项偏高标红
```

## 4.5 流程四：DR检查全流程

### Step 1: 创建DR申请单（卫生院公卫医生）

```
系统操作:
  体检单管理 → 找到目标居民体检单 → 点击"DR申请"
  或: DR管理 → DR申请单 → 新建

  填写:
  - 居民姓名/身份证（自动带入）
  - 检查部位: 胸部正位（标准项目）
  - 检查描述: 胸部X线检查（公卫年度体检）

  提交后系统生成:
  - DR申请单号: DR20260325143022001
  - 条码号:     BC20260325143022001（全局唯一）
  - 状态:       0（待扫码）
```

### Step 2: 打印并贴条码

```
打印操作:
  DR申请单列表 → 找到申请单 → 点击"打印条码"
  → 调用打印机API输出条码标签（宽50mm × 高30mm）

  条码内容：
  ┌─────────────────────────────────┐
  │  BC20260325143022001            │
  │  ████████████████████████████  │
  │  张三明  男  1958-03-15         │
  │  胸部正位  申请医生:李医生       │
  └─────────────────────────────────┘

  将条码贴于纸质申请单右上角，与居民一同前往DR室
```

### Step 3: DR技师扫码签到

```
DR技师操作:
  → 打开系统 → DR管理 → DR扫码签到
  → 光标在输入框（页面加载后自动聚焦）
  → 扫码枪扫描申请单条码 → 回车

系统响应:
  □ 条码存在且状态=0(待扫码)
    → 显示申请单详情（姓名/部位/申请医生）
    → 状态更新: 0 → 1（已扫码）
    → 记录scanTime、scanUserId

  □ 条码不存在
    → 提示: "条码不存在，请核查"

  □ 已扫码/已完成
    → 提示: "该申请单已扫码，状态: 已签到"（防止重复操作）

技师操作:
  → 点击"继续扫码"（准备下一位）
  → 完成DR检查后，点击"标记检查完成"
     状态: 1 → 2（已完成）
```

### Step 4: 医生出具DR报告

```
放射科医生操作:
  → DR管理 → DR申请单 → 筛选"已完成"
  → 点击申请单 → "报告"按钮

  填写报告:
  影像所见: [描述影像所见，如双肺纹理清晰，心影不大...]
  诊断意见: [如双肺未见明显活动性病变]
  上传影像: 选择DCM/JPG文件（最大100MB）

  → 点击"提交报告"
  状态: 2 → 3（已完成，待上传）
```

### Step 5: 上传至公卫平台

```
系统操作:
  DR报告 → 点击"标记已上传"（或自动定时任务）
  状态: 3（已上传）

  记录:
  upload_status: 0 → 1
  upload_time: 当前时间
```

## 4.6 流程五：数据上报县域公卫平台

### 自动上报机制

```
【定时任务配置（每日23:00）】
触发器: @Scheduled(cron = "0 0 23 * * ?")

上报内容:
1. 当日完成体检单列表（status=2）
2. 各类检验结果（check_result，按category汇总）
3. DR报告（dr_report，upload_status=0的待上传记录）
4. 异常指标统计（abnormal_flag=1/2的结果数量）

上报格式: JSON → 县公卫平台API接口
上报结果: 记录upload_task表（成功/失败/重试次数）
```

### 手动上报（补发）

```
系统管理 → 数据上报 → 选择日期范围 → 点击"手动上报"
→ 系统将该时间段内状态异常的上报记录重新推送
→ 结果回填upload_task.status
```

## 4.7 流程六：体检结果反馈与健康指导

```
【居民结果告知流程】
1. 体检完成后，医生打印体检报告（PDF）
2. 异常指标居民: 医生面谈健康指导
   - 血糖异常 → 建议复查/转诊
   - 血压异常 → 纳入高血压管理
   - DR异常   → 附DR报告单
3. 体检报告单归入纸质档案（与系统电子档案对应）
4. 系统备注字段记录随访建议

【慢病转入管理】
体检发现高血压/糖尿病患者:
→ 居民档案 → 编辑 → 勾选chronic_flag（慢病标记）
→ 自动进入慢病管理队列
→ 下次随访计划系统提醒
```
