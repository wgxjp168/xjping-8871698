## 11.2 V1.1 版本规划（上线后3个月内）

### 核心功能加固

**1. 安全加固**
```
□ 登录失败锁定（5次失败→锁30分钟）
□ 操作日志完善（记录所有增删改操作的前后值）
□ 密码策略强制（复杂度要求、90天定期修改）
□ 接口限流（Spring Cloud Gateway Rate Limiter）
□ 身份证号/手机号脱敏显示（仅部分权限可查完整）
```

**2. 数据质控规则引擎**
```java
// 可配置的质控规则，存储在数据库
// 规则示例:
{
  "ruleCode": "QC_GLU_HIGH",
  "itemCode": "GLU",
  "operator": ">",
  "threshold": "6.1",
  "level": "WARNING",
  "message": "空腹血糖偏高，建议复查OGTT"
}
// 支持运营人员在系统内维护规则，无需改代码
```

**3. 数据上报对接（省/市公卫平台）**
```
上报格式: 按省卫健委接口规范（JSON/XML）
上报内容: 体检结果、DR报告（脱敏后）
自动时机: 每日23:00定时上报 + 手动补发
状态追踪: upload_task表记录成功/失败/重试
```

**4. 电子签名（医生签名）**
```
方案: 集成国产CA证书（如天威诚信/WoSign）
范围:
  - 检验结果审核签名
  - DR报告医生签名
  - 体检结论签名
合规要求: 符合《电子病历基本规范》
```

**5. 批量操作优化**
```
□ 批量建体检单（从花名册批量导入，一次性创建多个）
□ 体征数据批量导入（从现场采集Excel导入）
□ 批量审核（同类正常结果一键审核）
□ 批量导出（体检报告PDF批量打包下载）
```

## 11.3 V1.2 版本规划（上线后6个月）

### 智能化与扩展

**1. 慢病管理模块**
```
功能:
  - 高血压患者随访计划管理
  - 糖尿病患者随访跟踪
  - 随访到期提醒（短信/系统消息）
  - 趋势图（血压/血糖变化趋势）
  - 慢病管理统计报表

数据来源:
  - 体检结果自动标记（血糖>6.1 → 进入糖尿病随访队列）
  - 医生手动标记
```

**2. AI辅助决策（提示功能）**
```
基于规则的智能提示（非AI模型，规则库驱动）:
  - 多次体检血糖均偏高 → "建议转诊内分泌科"
  - BMI>28 + 血糖偏高   → "代谢综合征风险提示"
  - DR发现异常征象      → "建议CT进一步检查"
  - 血压连续2次≥140/90  → "建议纳入高血压管理"

未来规划（V2.0后）: 接入大模型API进行智能分析
```

**3. 移动端适配**
```
方案: PWA（渐进式Web应用）
  - Vue3项目增加 manifest.json + Service Worker
  - 关键页面适配手机屏幕（响应式布局）
  - 优先适配页面: DR扫码签到、体征录入、结果查询
  - 支持安装到手机桌面（无需App Store）

后续规划: 微信小程序（V2.0）
```

**4. 消息推送系统**
```
推送渠道:
  □ 企业微信（卫生院内部人员）
  □ 短信（紧急告警、危急值通知）
  □ 系统内消息（操作提醒）

推送场景:
  - 危急值 → 立即短信通知主管医生
  - DR报告完成 → 通知申请医生
  - 体检完成 → 通知公卫专干汇总
  - 数据上报失败 → 通知信息员
```

## 11.4 V2.0 版本规划（上线后12个月）

### 平台化升级

**1. 微服务拆分与独立数据库**
```
当前: 共用一个 hd_public_health 数据库（单体数据库）
V2.0: 各服务独立数据库，跨服务通过API访问

hd-resident → resident_db
hd-check    → check_db
hd-device   → device_db
hd-dr       → dr_db
hd-auth     → auth_db

优势: 独立扩容、故障隔离、技术栈灵活
```

**2. 微信小程序**
```
居民端（可选，按需开发）:
  - 查询本人历史体检结果
  - 预约下次体检
  - 查看体检报告（DR影像）

卫生院端:
  - 移动端扫码签到（替代PC端DR扫码）
  - 下乡体征采集（手机录入）
  - 收到消息推送
```

**3. 大数据分析平台**
```
采集范围: 全县历年公卫体检数据
分析维度:
  - 疾病谱分析（各病种发病率趋势）
  - 地域分布（哪个镇高血压高发）
  - 年龄分布（各年龄段健康状况）
  - 设备效率分析

输出形式:
  - 管理驾驶舱（大屏）
  - 年度健康报告自动生成
  - 卫健局决策支持报告
```

**4. 开放API平台**
```
面向对象: 第三方系统（HIS/LIS/PACS）
接口形式: RESTful + OpenAPI 3.0规范
鉴权方式: OAuth2.0 Client Credentials
开放接口:
  - 居民档案查询
  - 体检结果查询
  - DR报告查询
使用场景:
  - 县医院HIS直接调取居民公卫体检历史
  - 省卫健局平台对接
```

## 11.5 设备扩展规划

| 阶段 | 新增设备类型 | 设备例子 | 接入方式 |
|------|------------|---------|---------|
| V1.1 | 心电图仪 | 迈瑞ECG-1350 | ASTM/HL7 |
| V1.1 | 眼底照相机 | 拓普康TRC-NW400 | DICOM/私有协议 |
| V1.2 | 骨密度仪 | 豪洛捷Horizon | ASTM/专用API |
| V1.2 | 超声仪（B超）| 迈瑞DC-40 | DICOM |

**协议扩展规划**
```
当前支持: ASTM E1381/E1394 (全部11台设备)
V1.1新增:
  - HL7 v2.x (医院信息系统标准)
  - DICOM (影像设备标准, 支持眼底/B超)
V1.2新增:
  - RS-232串口转TCP (旧式设备改造)
  - USB HID (便携式血糖/血压计)
```

## 11.6 版本发布规范

```
版本号规则: MAJOR.MINOR.PATCH
  MAJOR: 架构重大变更（如多数据库、微信小程序）
  MINOR: 功能新增（如慢病管理、电子签名）
  PATCH: Bug修复、安全补丁、性能优化

发布节奏:
  Patch版本: 按需发布，最小化停机
  Minor版本: 每季度一个，维护窗口发布
  Major版本: 年度规划，完整验收流程

发布流程:
  开发完成 → 测试环境验证 → UAT → 灰度发布(5%) → 全量

回滚策略:
  保留最近2个版本镜像，5分钟内可回滚
  数据库变更脚本必须提供回滚SQL
```
