# 01 · 项目整体建设成果总结

## 1.1 项目背景与目标

惠东县辖区面积约3520平方公里，下辖16个镇（街道）、215个行政村，农村居民基本公共卫生服务体检长期面临：

- **设备分散**：各卫生院自购设备，型号各异（11种），数据孤岛
- **人工转录**：医生手工抄写检验结果，误差率高达3‰
- **DR低效**：县医院DR设备集中，基层申请→转运→等待周期长达3～5天
- **数据滞后**：公卫数据上报依赖Excel，每季度手工汇总，时效差
- **权限混乱**：系统无统一账号体系，部分机构共用账号

**建设目标**：搭建覆盖全县、设备直联、数据自动流转的区域公卫体检集中信息系统，实现"一次建档、全程跟踪、数据共享、实时上报"。

## 1.3 核心技术亮点

### ① ASTM全协议解析引擎
- 实现完整 ASTM E1381（物理层）+ E1394（数据层）解析
- 支持帧级控制字符（ENQ/ACK/EOT握手、ETX/ETB分帧、校验和验证）
- 单 TCP 监听端口（7100）自动识别11种设备
- 原始报文完整保存，支持回溯与重解析

### ② DR条码全程追溯
- 申请单创建时系统生成全局唯一条码（`BC` + 时间戳 + 随机位）
- 扫码签到一键触发状态流转（待扫→已签到→已完成→已上传）
- 每一步操作记录操作人、时间，全程可审计

### ③ 统一JWT网关鉴权
- 所有业务请求经 Gateway 过滤，下游服务无鉴权逻辑
- Redis 黑名单实现"即时失效"退出（无需等 token 过期）
- X-User-Id / X-Username / X-Permissions 请求头注入，下游直接使用

### ④ 微服务数据隔离
- 5个微服务独立部署、独立扩容
- 共用同一 MySQL 库但 schema 隔离（可平滑迁移为独立库）
- 各服务单独 Knife4j API 文档，接口自描述
